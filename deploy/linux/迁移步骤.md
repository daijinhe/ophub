# 云枢 OpsHub · 迁移到 Linux 服务器 · 操作步骤

目标形态：**Win11 本地开发 → 推内网 Harbor → Linux 服务器拉取运行**。
内网与互联网隔离，所以**服务器上绝不构建镜像**，只 pull。

本次迁移参数（已确认）：

| 项 | 值 |
| --- | --- |
| 版本 | **v1.7.8** |
| Harbor | `harbor.internal.example` / 项目 `your-project` / `admin` |
| 镜像拉取 | 服务器能直连 Harbor（同一内网） |
| 数据 | 完整迁移（25 表 / 16 资产 / 2 用户） |
| 平台端口 | `10001` |

---

## 迁移前必须知道的三条

1. **PWD_ENC_KEY 必须原样搬过去**。它是资产里 SSH/sudo 密码的 AES 解密密钥。
   换成新值 = 库里所有已存凭据解不开，表现为"密码错误"，**且不可恢复**。
   JWT_SECRET 相反，可以（也建议）换新的强随机值，代价只是所有人重新登录一次。
2. **服务器上不要放源码、不要 build**。`deploy/linux/docker-compose.yml` 已经删掉了 `build:` 段，
   四个服务全部靠 pull；内网既拉不到公网基础镜像，也访问不了 goproxy.cn / npmmirror。
3. **compose 项目名固定为 `ophub`**（compose 里顶层 `name: ophub`）。
   数据卷名是 `ophub_pgdata` 这种，由项目名派生 —— 项目名一变，数据就"凭空消失"。

## 第 1 步 · 本地 Win11 导出数据包

在 **Git Bash** 里（项目根目录）执行：

```bash
bash deploy/linux/export-from-windows.sh
```

产物在 `dist/migrate/`：

```
ophub.dump          数据库（自定义格式，224K）
backend-data.tgz     known_hosts.json 等运行时数据
backend-uploads.tgz  上传的 Excel 等文件
ansible-data.tgz     /etc/ansible 配置
PWD_ENC_KEY.txt      ★ 解密密钥，务必一起带走
```

> 脚本已实测通过（`bash deploy/linux/export-from-windows.sh` 与 `cd deploy/linux && sh export-from-windows.sh`
> 两种方式都跑过，产物均正确）。它全程用 `docker exec` 在容器内打包 + `docker cp` 拷出，不做宿主机目录挂载。
>
> ⚠️ 已修掉的坑：Git Bash 会把 `/tmp/xxx` 这类 POSIX 路径**自动改写**成 `C:/Users/<你>/AppData/Local/Temp/xxx`
> 再传给 `docker.exe`，容器内没有这个 Windows 路径，报 `pg_dump: could not open output file`。
> 用 `bash` 跑有时不触发、**用 `sh` 跑必触发**。脚本已在开头 `export MSYS_NO_PATHCONV=1` 并改用 `/var/tmp`，
> 两套保险都上了，不要再改回 `/tmp`。

## 第 2 步 · Linux 服务器装环境

先确认架构（镜像都是 amd64）：

```bash
uname -m          # 必须是 x86_64
```

### 2.1 Docker

```bash
# 有外网：
curl -fsSL https://get.docker.com | sh
systemctl enable --now docker

# 无外网：在有网的机器下载静态二进制 https://download.docker.com/linux/static/stable/x86_64/
# 解压后把 docker/* 拷到 /usr/bin/，再手工配 systemd 服务
```

### 2.2 docker compose（v2 插件）

```bash
mkdir -p /usr/libexec/docker/cli-plugins
# 从 https://github.com/docker/compose/releases 下载 docker-compose-linux-x86_64
cp docker-compose-linux-x86_64 /usr/libexec/docker/cli-plugins/docker-compose
chmod +x /usr/libexec/docker/cli-plugins/docker-compose
docker compose version      # 应输出 v2.x
```

> 只有 compose **v1** 也行，但它不认顶层 `name:`，项目名会取目录名 ——
> **此时部署目录必须叫 `ophub`**，否则卷名变成别的，数据对不上。

### 2.3 信任 Harbor（HTTP 仓库必做）

```bash
mkdir -p /etc/docker
cat > /etc/docker/daemon.json <<'EOF'
{
  "insecure-registries": ["harbor.internal.example"]
}
EOF
systemctl restart docker
docker info | grep -A2 "Insecure Registries"      # 应能看到该地址
```

### 2.4 登录 Harbor

```bash
docker login harbor.internal.example -u admin
# 密码：<HARBOR_PASSWORD>
```

### 2.5 建部署目录并放文件

```bash
mkdir -p /opt/ophub
cd /opt/ophub
```

把 `deploy/linux/` 下的 **`docker-compose.yml`、`.env.example`、`import-on-linux.sh`**
三个文件放进来，再把本地 `dist/migrate/` 整个目录拷进来（U 盘 / scp / 共享目录都行）：

```
/opt/ophub/
├── docker-compose.yml
├── .env.example
├── import-on-linux.sh
└── migrate/
    ├── ophub.dump
    ├── backend-data.tgz
    ├── backend-uploads.tgz
    ├── ansible-data.tgz
    └── PWD_ENC_KEY.txt
```

## 第 3 步 · 填 .env（最关键的一步）

```bash
cp .env.example .env
vi .env
```

必须改的三处：

```bash
# 1) 生成新 JWT 密钥
openssl rand -base64 48
#    把输出粘到 JWT_SECRET=

# 2) PWD_ENC_KEY —— 原样照搬，一个字符都不能改
cat migrate/PWD_ENC_KEY.txt
#    把内容粘到 PWD_ENC_KEY=

# 3) 脚本目录（服务器上没有这个目录就改成实际存在的路径）
SCRIPT_HOST_ROOT=/data/jenkins_home/scripts/Java_Start_Stop_SH
```

镜像地址已按 v1.7.8 预填好，不用改：

```bash
POSTGRES_IMAGE=harbor.internal.example/your-project/postgres:16
REDIS_IMAGE=harbor.internal.example/your-project/redis:7.4.10
BACKEND_IMAGE=harbor.internal.example/your-project/ophub-backend:v1.7.8
FRONTEND_IMAGE=harbor.internal.example/your-project/ophub-frontend:v1.7.8
```

> `import-on-linux.sh` 会**自动比对** `.env` 里的 PWD_ENC_KEY 和 `migrate/PWD_ENC_KEY.txt`，
> 不一致直接拒绝执行 —— 这一步不用靠人眼盯。

---

## 第 4 步 · 一键拉取 + 还原 + 启动

```bash
cd /opt/ophub
bash import-on-linux.sh
```

脚本按顺序做六件事：拉镜像 → **只起 postgres/redis** → 还原数据库 → 还原三个卷 → 起全部服务 → 打印验收清单。

> 为什么必须先起数据库、后起 backend：backend 启动会跑 AutoMigrate 并 seed 初始数据，
> 先起它再灌库会撞车。脚本已经把这个顺序固定死了。

成功后会打印：

```
还原完成：表 25 张 / 资产 16 条 / 用户 2 条
```

## 第 5 步 · 验收

| # | 检查 | 期望 |
| --- | --- | --- |
| 1 | `docker ps` | 4 个 ophub-* 容器都是 Up |
| 2 | 浏览器 `http://<服务器IP>:10001` | 打开登录页，admin/admin123 能进 |
| 3 | 资产列表 | **16 条** |
| 4 | 用户管理 | **2 个** |
| 5 | Ansible 远程 → 挑一台 → 测试连接 | **返回 PING-OK** ← 最关键 |

第 5 项一条同时证明三件事：数据全 + PWD_ENC_KEY 对 + 服务器到目标机网络通。
它过了，迁移才算真的成功。

常用排查：

```bash
docker logs -f ophub-backend          # 后端起不来先看这里
docker logs ophub-postgres | tail -30
docker exec ophub-postgres psql -U ophub -d ophub -c "\dt"   # 看表
ss -lntp | grep 10001                  # 端口在不在听
```

## 第 5.5 步 · 迁移后的两项运维配置（可选，推荐）

平台跑起来后，下面两件事不是必须的，但能显著提升后续运维体验。

### 5.5.1 把 PG 数据从 docker volume 搬到主机目录

现在数据还在 docker volume `ophub_pgdata` 里（容器内 `/var/lib/postgresql/data`），
主机上 `ls` 看不到也搬不走。换成主机目录后，备份 / 迁移 / 看一眼都方便。

```bash
cd /opt/ophub
bash deploy/linux/move-pgdata-to-host.sh
```

默认目标 `/data/your-project/ophub/data/postgresql`（也可用第一个参数指定）。
脚本会：
1. 先把当前 compose + 当前 docker volume 备份到 `~/ophub-pgmove-bak-<时间戳>/`
2. 把卷内容 tar 到目标主机目录 + `chown 999:999` 修正权限
3. sed 把 compose 里的 `pgdata:/var/lib/postgresql/data` 改为主机目录挂载
4. 重启全部容器
5. 打印「表 25 / 资产 16 / 用户 2」验收数字

> ⚠️ 脚本会保留旧 docker volume 不删（确认无误后手工 `docker volume rm ophub_pgdata`）。

如果改完起不来（`permission denied` 看 docker logs），八成是主机目录权限：
```bash
chown -R 999:999 /data/your-project/ophub/data/postgresql
# 或者退一步 chmod 777（不安全但能起来）
chmod -R 777 /data/your-project/ophub/data/postgresql
```

### 5.5.2 让「Java 启停脚本管理 · 平台本机」功能可用

现象是页面进得去但服务列表空白 —— 容器「本机」= 容器文件系统，看不到主机目录。
要把主机上的脚本根目录挂进容器。

服务器上假设脚本根目录是 `/data/jenkins_home/scripts/Java_Start_Stop_SH`，
里面已经有 `China Mobile`、`order-service` 这种服务目录。

```bash
cd /opt/ophub
bash deploy/linux/setup-scripts-dir.sh
```

脚本会：
1. 建主机目录（已存在则不动）
2. 把 `SCRIPT_HOST_ROOT=...` 写进 `.env`
3. 提示 `docker compose up -d --no-build backend`

然后进平台 → Java 启停脚本管理 → 刷新，应该能看到你的服务目录了。

> 自定义路径：`bash deploy/linux/setup-scripts-dir.sh /your/script_root`

## 第 6 步 · 以后怎么发新版（日常流程）

**本地 Win11（Git Bash）：**

```bash
bash scripts/harbor_release.sh --git "feat: xxx"
```

它会升版本号 → 提交 → 打 tag → 推 Gitea → 构建 → 推 Harbor。结束时打印新的镜像 tag。

**Linux 服务器：**

```bash
cd /opt/ophub
vi .env                       # 把 BACKEND_IMAGE / FRONTEND_IMAGE 的版本号改成新的
docker compose pull
docker compose up -d
```

> ⚠️ 两个坑，现在就要知道：
> 1. 本地当前 `VERSION` 是 **v1.7.4**（你要求回滚后停在这里），而 tag `v1.7.5~v1.7.8` 已经存在。
>    下次发版 `release.sh` 默认 +1 会撞 `v1.7.5`，必须显式指定版本号：
>    `bash scripts/harbor_release.sh --git "xxx" -v v1.7.9`
> 2. 本地仓库现在是 **detached HEAD**（停在 v1.7.4），`release.sh` 会拒绝提交。
>    发版前先 `git checkout main`。

---

## 出问题怎么回滚

服务器上：

```bash
cd /opt/ophub
vi .env                       # 把版本号改回上一个（v1.7.8 → 上一个可用版本）
docker compose pull
docker compose up -d
```

数据不受影响（在数据卷里）。只有发生了**跨版本的表结构变更**才需要重新导库，
v1.7.x 内部升级没有过这种变更。
